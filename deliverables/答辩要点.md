# 答辩要点（Q&A 速查）

> 配合 `设计文档.md` 使用。先讲结论，再讲依据；被追问时回到「单一事实源」。

---

## 一、三个必答题

### Q1：情感分析准确率是多少？为什么是这个水平？

**结论**：在 75 条人工标注验证集上，实测 **准确率 82.7%、Cohen's Kappa 0.74**（高度一致）。

**依据**：
1. 验证集 75 条（正/中/负各 25），直接运行线上同一个 `SentimentAnalyzer`，未另写一套。
2. 分类别：正向 F1 0.96、中性 0.79、负向 0.72；**正向/负向 Precision 均 1.00**——判出极性基本不会错。
3. 误差结构健康：13 条错分**全是「弱极性判中性」，零极性反转**（混淆矩阵 POS↔NEG 两格为 0）。
4. Kappa 0.74 排除偶然一致，比单看准确率更可信；低置信样本标 `low_confidence` 交人工复核。
5. 82.7% 高于设计预期的 65~75%，原因是验证集由作者构建、句子较清晰；真实模糊数据会回落，这一差距在评估报告里已写明。

**追问「负向 Recall 只有 0.56 怎么办？」**：默认负向阈值 -1.5 偏保守，单个负向词（-1.0）越不过边界。敏感性分析显示放宽到 -1.0 可到 90.7%，但同集调参有过拟合风险，且教育语境下「误判中性为负向」代价更高，故保留保守默认、列入后续工作。

**追问「为什么不用大模型做分类？」**：分类结论要求可复现、可逐词复核、断网可用；大模型每次输出不同、依赖网络与费用，且无法回答"为什么这条判负向"。本项目把大模型放在**摘要建议**这个允许措辞差异的位置（`Spring AI` + 规则双通道，见 Q4），分类仍用词典法。

### Q2：为什么「审核通过」不等于「已发布」？

**结论**：这是两个正交维度，合并会直接导致「撤回」无法实现。

**依据**：
1. `status` 回答「内容是否合格」，`published_at` 回答「是否推送给学生」。
2. 场景：内容合格但需等学期末统一发布；或误发布后要收回。若合并成一个状态，撤回后既不是「待审核」也不是「已通过」，**没有合法落点**。
3. 拆开后：撤回 = `published_at` 置 NULL + 记录 `withdrawn_at`，内容仍是 APPROVED，可再次发布（再发布需理由 ≥5 字，保证「为何放回」可查）。
4. 统计口径唯一：只有 `status=APPROVED 且 published_at 非空` 才纳入，学生端同理。

### Q3：为什么是 n≥5（k=5）？为什么不是 3 或 10？

**结论**：k=5 是 k-匿名的常用下限，用于防止从小样本聚合反推个人。

**依据**：
1. 2~4 条点评的高频词几乎就是原文关键词，放宽到 3 收益为零、风险不为零。
2. 单一配置键 `analysis.min-sample`，同时作用于饼图 / 趋势 / 词云 / 下钻；现场把它从 5 改成 6，四张图必须同时变化——**证明口径统一**。
3. 更关键的是**桶级门禁**：整体 40 条足以放行，但某月只有 2 条时，点进去就是 2 个学生的完整点评。所以下钻按**桶级样本量**判定，而不是整体。

### Q4：Spring AI 是怎么接的？为什么默认关闭？

**结论**：接在「点评摘要建议」这个位置，默认关闭；关闭 / 断网 / 无 Key / 超时全部自动回落规则实现，接口结构不变。

**依据**：
1. **不用 starter 自动配置**。`spring-ai-starter-model-openai` 绑定 Boot 3.4.x，本项目 3.2.5；更严重的是它**无 Key 时会让整个应用启动失败**——等于把可选功能做成启动硬依赖。改用 `spring-ai-openai` + `spring-ai-client-chat` 显式装配 `OpenAiApi → OpenAiChatModel → ChatClient`，并在 `LlmSummarySuggester` 内**懒初始化**：构造阶段不连网、不校验 Key。
2. **兼容性有测试兜底**。Boot 3.2.5 与 Spring AI 1.0.0（按 3.4.x 编译）能否共存不靠猜，`LlmSummarySuggesterTest` 有一条断言直接跑通整条构建链路。
3. **超时是功能的一部分**。连接 3s / 读取 10s；模型抖动时导师不能转圈 30 秒。
4. **输出必须过闸**。长度、条数、格式（`摘要：` / `建议：`两行）任一不合规即判失败并回落——半截 JSON 塞进审核意见比没有建议更糟。
5. **降级实现独立可用**。规则版用「情感结论 + 预检问题清单」拼装，9ms 返回，断网时表现一致。只在模型可用时才有输出的功能，本质是把可用性外包给第三方。
6. **不落库、不改状态**。摘要只出现在编辑弹窗里，不写 `comment` 表、不进审核流程——避免草稿期反复点击堆垃圾数据，也避免模型版本变化后旧摘要与正文不对应。
7. **配置由教务自助，不用改代码或重启**。`admin` →「AI 配置」→ 填 Key → 保存。Key 存 `sys_config` 表，优先级「数据库 > 环境变量 > 空」；保存时失效缓存，`LlmSummarySuggester` 按配置版本号（`updated_at` 毫秒戳）重建 `ChatClient`。**填一次，全体导师生效**——因为 Key 是服务端共享配置，不是每个账号一份。
8. **密钥不外泄**。读取接口只返回 `sk-****cdef` 掩码，明文不出服务端；写接口仅教务可用（导师访问 403）；操作日志只记"apiKey=重设"，不记内容。不做加密存储的理由：加密需要密钥，密钥又要放环境变量，等于把一个配置变成两个，攻击面没缩小、运维复杂度翻倍。

**追问「这不就是套壳调 API？」**：区分在哪一层用。分类（要可复现可答辩）用词典法，摘要（允许措辞差异）用模型，两者输出结构一致、可互换，且降级路径能独立完成同样的事。

### Q5：AI 小助手和摘要建议有什么区别？为什么学生也能用？

**结论**：同一个 Key、同一个 ChatClient，但用途、提示词、限流策略完全不同。

**依据**：
1. **摘要建议**是导师写点评时的编辑辅助，输出固定两行（`摘要：` / `建议：`），格式不合规就回落规则实现——它的输出要进审核流程，不能是自由文本。
2. **小助手**是多轮对话，输出是自由文本，不落库、不进任何流程。学生用它读懂点评并落地成计划，导师用它检查点评是否具体，教务用它理解口径。
3. **场景由后端按登录角色决定**，请求体里没有 `scene` 字段。学生拿不到教务口径提示词——**提示词本身就是权限边界**，和 DTO 里不放敏感字段是同一个思路。
4. **共用 Key 但配额策略不同**：对话按用户限流（12 次/分、150 次/日），摘要不限流（触发频率低、单人单次）。
5. **无 Key 时小助手返回说明文案（`source=DISABLED`）而不是报错**。助手默认就是关的，把"没配 Key"做成接口报错属于误伤。

**追问「学生问'我能不能保研'怎么办？」**：提示词里明确禁止承诺成绩/保研/评优/奖学金，并要求涉及具体结论时写"以学院和导师的正式通知为准"。这类问题模型会拒绝并引导回学业。这条不是靠前端拦，是写在系统提示词里的硬约束。

**追问「会不会被刷爆额度」**：按用户限流 + 日上限，且先扣配额再调模型（失败也计数，防止失败重试无限打）。单机内存实现，多实例部署需换 Redis 或网关限流——这条已写进局限。

## 二、高频追问

| 追问 | 回答要点 |
| --- | --- |
| 为什么不做词频缓存表？ | 派生数据无单一失效源，退回改稿/撤回/再发布会静默不同步且不报错；百条量级实时分词是毫秒级。 |
| 两人同时审核怎么办？ | 条件更新 `WHERE status=PENDING` + 影响行数判定，后到者 409「状态已变化」，不覆盖。 |
| 为什么没有批量发布？ | 批量 `WHERE id IN(...)` 会绕过逐条状态校验，是状态机被破坏的主要入口。 |
| 学生能看到情感标签吗？ | 不能。情感分析的对象是「导师写的文本」，展示给学生会被误读为「对自己的评价」，属语义错位。 |
| 审核意见会泄露给学生吗？ | 不会。学生端 DTO 在数据层就不含审核意见与情感标签，不是「前端不显示」。 |
| 分析结果会不会用旧数据？ | 不会。`content_hash`（正文 SHA-256）+ `method_version` 双匹配才复用，改一个字或升级词典都会重算。 |
| 当月数据不完整怎么处理？ | 趋势图含当前未完结月，用虚线/斜纹标注「更新中」，不与已完结月混为一谈。 |
| 隐私怎么脱敏？ | 归一化后对姓名/学号/手机号/身份证/邮箱做掩码，再参与分词与聚合。 |
| 为什么用 Sa-Token 不用 Spring Security？ | 轻量、API 友好、与前后端分离契合；权限仍在 Service 层判定，不依赖框架。 |
| 数据一致性怎么保证？ | 单一入口 `CommentScope.published()`；报表一次 `dashboard` 聚合返回，避免多请求数字对不上。 |
| 导师能看到全院的词云吗？ | 不能。`/api/report/my-dashboard` 的 `teacherId` 由登录态强制注入，请求里传了也不生效；返回体不含审核队列统计。 |
| 为什么导师端 KPI 要单独算？ | 教务 KPI 里的草稿/待审/退回走全量口径（`count(null,status)`），直接复用会让导师看到全院草稿数。 |
| 为什么档案只停用不删除？ | 点评、审核记录、操作日志都引用档案，物理删除会产生"无主点评"。停用保留可追溯性。 |
| 停用导师时为什么会被拦？ | 有未完结点评（草稿/待审核/退回）时默认拒绝并报条数，否则这些点评永久卡在流程里；确认后可 `force=true` 强制停用。 |
| 新建账号的密码怎么给？ | 用户名 = 工号/学号，初始密码 `Mentor@2026`（可配置），**只在创建与重置的那一次响应里返回**，之后不可再查。 |
| 教务改完 Key 要重启吗？ | 不用。写库后失效缓存，按配置版本号重建 ChatClient，导师端下一次调用就用新的。 |
| 密钥存在哪？安全吗？ | 存 `sys_config` 表，明文；但接口只回掩码、写接口仅教务、日志不记内容。生产化建议接 KMS 或只走环境变量。 |
| 为什么不做加密存储？ | 加密需要一个加密密钥，那个密钥又要放环境变量——一个配置变两个配置，攻击面没缩小。真正的防线是"明文不出服务端"。 |
| 演示时 Key 会丢吗？ | `demo` profile 是 H2 内存库，重启后后台填的 Key 会清空（环境变量不受影响）；MySQL 模式持久化。 |
| 小助手会把学生问的问题存下来吗？ | 不会。对话只在浏览器内存里，刷新即清空；后端不落库，因为落库就要配套脱敏、保留期、删除机制。 |
| 三个角色共用一份 Key，会不会互相干扰？ | 不会。配额按用户 ID 独立计数；提示词按角色切换；摘要与对话共用 ChatClient 但互不影响。 |

## 三、5 分钟演示动线

1. 登录 `admin / 123456` → 统计报表，先念一遍「口径行」。
2. 切班级到 **计科2207**（n=4）→ 三图空态；切 **计科2205**（n=5）→ 放行。
3. 点趋势图 **4 月**（计科2208 后月仅 1 条）→ 桶级下钻被禁用。
4. 审核队列 → 一条演示「通过发布」，一条演示「仅通过」，一条「退回」，一条「驳回」（注意字数门槛 5/10/10/20）。
5. 发布管理 → 待发布里把「仅通过」的发布；已发布里撤回一条（≥10 字）→ 学生端立即消失。
6. 审核详情抽屉 → 展开「情感分析依据」，指出命中词与否定标记。
7. 师生管理 → 新增导师（工号即登录名，保存后弹一次初始密码）→ 用新账号登录成功；再试停用 `teacher01`，被拦下并报「还有 12 条未完结点评」，二次确认后才停用，停用后登录 403。
8. 退出，登录 `teacher01 / 123456` → 「我的画像」：情感环图 + 趋势 + 词云，数据只有本人 40 条（不是全院 56 条），页面上没有审核队列统计。
9. 「我的点评」→ 新建点评 → 写 30 字以上 → 点「生成摘要建议」→ 展示摘要 + 3 条建议，标签是「规则生成」（黄）。**断网演示也不影响**。
10. 回 `admin` →「AI 配置」→ 填 Key → 保存 → 点「测试连接」看到成功（或看到「HTTP 401：Key 无效」这种可读提示）；**不重启**切回 `teacher01` 再点按钮 → 标签变蓝（模型生成）——证明 Key 填一次全体导师生效。
11. 再回后台点「清除密钥」→ 导师端立刻退回黄标。这就是降级开关的现场演示。
12. 退出，登录 `student01 / 123456` → 只看到 5 个字段，无审核意见、无情感标签。
13. 点右下角悬浮按钮 → AI 小助手，快捷问题显示的是学生视角（"帮我制定下周的复习计划"）；问一句看回复。切到 `admin` 再打开，快捷问题变成口径类（"k=5 是什么意思"）——同一份 Key，三套提示词。

## 四、风险与话术

- **被质疑准确率低**：主动给出 Kappa 与混淆矩阵，强调「低置信 + 人工复核」的设计，而不是辩解。
- **被质疑功能像 CRUD**：把重点拉回「双维度状态机 + 桶级隐私门禁 + 可解释分析 + AI 双通道降级」四个非平凡点。
- **被问工作量**：展示决策表（14 项）与测试基线（12 条）、55 个自动化测试，说明每个数字都有出处，不是拍脑袋。
