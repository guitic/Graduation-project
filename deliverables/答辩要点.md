# 答辩要点（Q&A 速查）

> 配合 `设计文档.md` 使用。先讲结论，再讲依据；被追问时回到「单一事实源」。

---

## 一、三个必答题

### Q1：情感分析准确率是多少？为什么是这个水平？

**结论**：在 75 条人工标注验证集上，实测 **准确率 82.7%、Cohen's Kappa 0.74**（高度一致）。

**依据**：
1. 验证集 75 条（正/中/负各 25），直接运行线上同一个 `SentimentAnalyzer`，未另写一套。
2. 分类别：正向 F1 0.96、中性 0.79、负向 0.72；**正向/负向 Precision 均 1.00**——判出极性基本不会错。
3. 误差结构健康：13 条错分**全是「弱极性判中性」，零极性反转**（混淆矩阵 POS↔NEG 两格为 0）。
4. Kappa 0.74 排除偶然一致，比单看准确率更可信；低置信样本标 `low_confidence` 交人工复核。
5. 82.7% 高于设计预期的 65~75%，原因是验证集由作者构建、句子较清晰；真实模糊数据会回落，这一差距在评估报告里已写明。

**追问「负向 Recall 只有 0.56 怎么办？」**：默认负向阈值 -1.5 偏保守，单个负向词（-1.0）越不过边界。敏感性分析显示放宽到 -1.0 可到 90.7%，但同集调参有过拟合风险，且教育语境下「误判中性为负向」代价更高，故保留保守默认、列入后续工作。

**追问「为什么不用大模型？」**：大模型不可复现、依赖网络与费用、难以解释；词典法可逐词复核，更契合「管理参考」定位。大模型作为扩展项仅提供辅助建议，不替代基础路径。

### Q2：为什么「审核通过」不等于「已发布」？

**结论**：这是两个正交维度，合并会直接导致「撤回」无法实现。

**依据**：
1. `status` 回答「内容是否合格」，`published_at` 回答「是否推送给学生」。
2. 场景：内容合格但需等学期末统一发布；或误发布后要收回。若合并成一个状态，撤回后既不是「待审核」也不是「已通过」，**没有合法落点**。
3. 拆开后：撤回 = `published_at` 置 NULL + 记录 `withdrawn_at`，内容仍是 APPROVED，可再次发布（再发布需理由 ≥5 字，保证「为何放回」可查）。
4. 统计口径唯一：只有 `status=APPROVED 且 published_at 非空` 才纳入，学生端同理。

### Q3：为什么是 n≥5（k=5）？为什么不是 3 或 10？

**结论**：k=5 是 k-匿名的常用下限，用于防止从小样本聚合反推个人。

**依据**：
1. 2~4 条点评的高频词几乎就是原文关键词，放宽到 3 收益为零、风险不为零。
2. 单一配置键 `analysis.min-sample`，同时作用于饼图 / 趋势 / 词云 / 下钻；现场把它从 5 改成 6，四张图必须同时变化——**证明口径统一**。
3. 更关键的是**桶级门禁**：整体 40 条足以放行，但某月只有 2 条时，点进去就是 2 个学生的完整点评。所以下钻按**桶级样本量**判定，而不是整体。

## 二、高频追问

| 追问 | 回答要点 |
| --- | --- |
| 为什么不做词频缓存表？ | 派生数据无单一失效源，退回改稿/撤回/再发布会静默不同步且不报错；百条量级实时分词是毫秒级。 |
| 两人同时审核怎么办？ | 条件更新 `WHERE status=PENDING` + 影响行数判定，后到者 409「状态已变化」，不覆盖。 |
| 为什么没有批量发布？ | 批量 `WHERE id IN(...)` 会绕过逐条状态校验，是状态机被破坏的主要入口。 |
| 学生能看到情感标签吗？ | 不能。情感分析的对象是「导师写的文本」，展示给学生会被误读为「对自己的评价」，属语义错位。 |
| 审核意见会泄露给学生吗？ | 不会。学生端 DTO 在数据层就不含审核意见与情感标签，不是「前端不显示」。 |
| 分析结果会不会用旧数据？ | 不会。`content_hash`（正文 SHA-256）+ `method_version` 双匹配才复用，改一个字或升级词典都会重算。 |
| 当月数据不完整怎么处理？ | 趋势图含当前未完结月，用虚线/斜纹标注「更新中」，不与已完结月混为一谈。 |
| 隐私怎么脱敏？ | 归一化后对姓名/学号/手机号/身份证/邮箱做掩码，再参与分词与聚合。 |
| 为什么用 Sa-Token 不用 Spring Security？ | 轻量、API 友好、与前后端分离契合；权限仍在 Service 层判定，不依赖框架。 |
| 数据一致性怎么保证？ | 单一入口 `CommentScope.published()`；报表一次 `dashboard` 聚合返回，避免多请求数字对不上。 |

## 三、5 分钟演示动线

1. 登录 `admin / 123456` → 统计报表，先念一遍「口径行」。
2. 切班级到 **计科2207**（n=4）→ 三图空态；切 **计科2205**（n=5）→ 放行。
3. 点趋势图 **4 月**（计科2208 后月仅 1 条）→ 桶级下钻被禁用。
4. 审核队列 → 一条演示「通过发布」，一条演示「仅通过」，一条「退回」，一条「驳回」（注意字数门槛 5/10/10/20）。
5. 发布管理 → 待发布里把「仅通过」的发布；已发布里撤回一条（≥10 字）→ 学生端立即消失。
6. 审核详情抽屉 → 展开「情感分析依据」，指出命中词与否定标记。
7. 退出，登录 `student01 / 123456` → 只看到 5 个字段，无审核意见、无情感标签。

## 四、风险与话术

- **被质疑准确率低**：主动给出 Kappa 与混淆矩阵，强调「低置信 + 人工复核」的设计，而不是辩解。
- **被质疑功能像 CRUD**：把重点拉回「双维度状态机 + 桶级隐私门禁 + 可解释分析」三个非平凡点。
- **被问工作量**：展示决策表（14 项）与测试基线（8 条），说明每个数字都有出处，不是拍脑袋。
