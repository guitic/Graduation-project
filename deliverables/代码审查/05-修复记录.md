### 2.2 为什么这么改（而不是只加一行 `requireAdmin()`）

只加 `requireAdmin()` 能堵住当前这个洞，但**根因还在**：映射写了两份，下次给 `AuditItem` 加字段，仍会有一处漏裁剪。

所以做了两件事：

1. **把"裁不裁"变成调用点必须回答的问题**——`AuditItemMapper.of(audit, forStudent)` 强制传布尔值，不传编译不过。
2. **把"谁能看"收敛到一处**——`audits()` 复用 `assertCanView()`，不再另写角色判断。

这对应红线 **R1（权限成对）** 与 **R5（DTO 裁剪单点）**。

### 2.3 顺带修掉的两个问题

| 问题 | 影响 | 说明 |
| --- | --- | --- |
| `detail()` 从未下发 `actionType` | 导师端时间线无法区分"通过并发布 / 仅通过 / 撤回"，全部退化成 `resultLabel` | 前端 `AuditTimeline.vue` 依赖 `a.actionType` 决定标题与图标。这个 bug 被 mapper 统一后自动修复 |
| `AuditQueue.vue` 导入 `history` 却从未调用 | 死代码 | 前端实际走 `commentDetail()`。**讽刺的是：这个漏洞接口从 UI 角度根本没人用，但仍是暴露的攻击面** |

```

反向：故意往 resources/db 追加一行 → ✗ 两份 schema 不一致 ... exit 1
```

## 十、第二轮：P1 技术债清理（2026-10-27）

第二轮处理的都是"不会立刻出错、但会一直错下去"的问题。顺序按**风险从低到高**：先改纯内部实现，最后动结构。

### 10.1 N+1 → 批量预加载（P1-1）

**原来**：`CommentService.toRow()` 每行查 6 次（导师、学生、班级、专业、情感、最近审核），pageSize=20 时约 120 条 SQL。导师/学生虽有两个 `HashMap` 缓存，但班级与专业随学生变化、情感与审核随点评变化，命中率接近零。

**现在**：`toRows(List<Comment>)` 先 `preload()` 一次性把六类关联对象取全，再逐行组装。

- 每个维度 1 条 `selectBatchIds` / `selectList`，**空集合直接跳过**（`IN ()` 是非法 SQL）
- 分页固定 **6 条 SQL**，与页大小无关
- `detail()` 走同一条路径（`toRows(List.of(c))`），不再有"列表一套、详情一套"

**为什么不是"补两个 cache"**：那只把 120 降到 ~80，且新增字段时还得记得加缓存。批量取是 O(1) 的，不会随页大小退化。

### 10.2 门槛单一来源（P1-4）

新增 `GET /api/meta/limits`，把 `AuditService` 的 6 个意见字数常量与 `analysis.min-sample` 一起下发；前端 `utils/limits.js` 是唯一读取点，`AuditQueue` / `Unpublished` 的"至少 N 字"与 placeholder 全部由返回值渲染。

前端保留一份 `DEFAULTS` 仅作接口不可用时兜底，注释里写明"必须与后端一致"——**兜底值是容错，不是第二来源**。

**验证**：把 `analysis.min-sample` 改成 60 重启，前端三处（口径行、空态文案、下钻门槛）同时变成 60，无需改前端一行代码。

### 10.3 配置分层与 demo 能力隔离（P1-5 / P1-6 / P1-7）

这一组里发现了一个**比审查报告更严重的问题**：

> `spring.sql.init.mode=always` + `db/schema.sql` 开头是 `drop table if exists` ⇒ **MySQL 模式每次重启都会清空全部业务数据**，而且不报错。

处理方式（不追求"自动建表"这个便利，换掉的是数据安全）：

| 项 | 改法 |
| --- | --- |
| 建表 | 默认 profile `mode: never`，首次部署手动 `mysql < sql/schema.sql`；README 写清命令与原因 |
| demo 库 | `mode: always`，但 `continue-on-error: false`——schema 缺列必须启动失败，不能吞掉 |
| 种子数据 | `@ConditionalOnProperty(app.demo-seed.enabled)`，只在 demo 为 true |
| 演示账号接口 | 同上开关；非 demo 返回 `{enabled:false, accounts:[]}`，登录页整块隐藏（原来匿名接口直接返回"统一密码 123456"） |
| SQL 日志 | 默认与 demo 均关闭（`StdOutImpl` 输出量大且与演示无关） |

### 10.4 状态机单元测试（P1-7）

新增 `AuditStateMachineTest`（21 条，4 个 `@Nested`）：

| 组 | 守什么 |
| --- | --- |
| OpinionThreshold（7） | 5 / 10 / 10 / 20 / 10 / 5 六档门槛，每档测"差一字被拒 + 达标放行" |
| ConditionalUpdate（5） | 断言 UPDATE 的 WHERE 含 `status`、`published_at IS NULL`；影响 0 行 → 409 |
