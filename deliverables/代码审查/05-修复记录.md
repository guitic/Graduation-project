### 2.2 为什么这么改（而不是只加一行 `requireAdmin()`）

只加 `requireAdmin()` 能堵住当前这个洞，但**根因还在**：映射写了两份，下次给 `AuditItem` 加字段，仍会有一处漏裁剪。

所以做了两件事：

1. **把"裁不裁"变成调用点必须回答的问题**——`AuditItemMapper.of(audit, forStudent)` 强制传布尔值，不传编译不过。
2. **把"谁能看"收敛到一处**——`audits()` 复用 `assertCanView()`，不再另写角色判断。

这对应红线 **R1（权限成对）** 与 **R5（DTO 裁剪单点）**。

### 2.3 顺带修掉的两个问题

| 问题 | 影响 | 说明 |
| --- | --- | --- |
| `detail()` 从未下发 `actionType` | 导师端时间线无法区分"通过并发布 / 仅通过 / 撤回"，全部退化成 `resultLabel` | 前端 `AuditTimeline.vue` 依赖 `a.actionType` 决定标题与图标。这个 bug 被 mapper 统一后自动修复 |
| `AuditQueue.vue` 导入 `history` 却从未调用 | 死代码 | 前端实际走 `commentDetail()`。**讽刺的是：这个漏洞接口从 UI 角度根本没人用，但仍是暴露的攻击面** |

**实测**：首次运行 `eslint .` 报 **45 个问题（38 error / 7 warning）**。

逐类处置：

| 类型 | 数量 | 处置 | 理由 |
| --- | --- | --- | --- |
| `'e' is defined but never used` | 38 | **改配置** `caughtErrors:'none'` | 本项目 `catch (e)` 普遍不用 `e`，因为提示已由 `request.js` 拦截器统一弹出。这是刻意设计，不是遗漏。改 38 处代码只会制造噪声 |
| `vue/attributes-order` | 7 | `eslint --fix` | 纯属性顺序，自动修复无风险 |
| `'history' is defined but never used` | 1 | **删导入** | 真问题：死代码 |

修复后：**`eslint .` 0 problems**。

### 5.2 后端

| 项 | 内容 |
| --- | --- |
| Spotless | `google-java-format` **AOSP 风格**（4 空格）。选 google 默认的 2 空格会让 56 个文件全量重排，AOSP 与现有代码一致 |
| Checkstyle | 只保留高价值语义规则：空 catch、`catch Throwable`、switch 缺 default、字符串 `==`、`System.out`、`printStackTrace` |
| 例外登记簿 | `config/checkstyle/suppressions.xml`，每条例外写明原因 + 确认人 + **撤销条件** |

**实测**：首次 `checkstyle:check` 报 **3 处违规**，全部是合理例外：

| 位置 | 规则 | 判定 |
| --- | --- | --- |
| `WordSegmenter.java:30` | IllegalCatch | **例外**：HanLP 初始化失败抛 `ExceptionInInitializerError` / `NoClassDefFoundError`，属 `Error` 非 `Exception`。收窄会让降级策略失效，整个系统跟着分词组件挂 |
| `WordSegmenter.java:44` | IllegalCatch | 同上（分词运行时降级） |
| `SentimentEvalTest.java:164` | System.out 禁令 | **例外**：评估脚本的 `System.out` 就是产出通道。`src/main` 的禁令仍全量生效 |

按流程要求"例外必须留痕"，写进 `suppressions.xml` 而非直接关规则。

修复后：**0 Checkstyle violations**。

### 5.3 遇到的三个真实坑（已解决，供参考）

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| `@eslint/js` 默认装 10.x | `ERESOLVE` 与 eslint 9 冲突 | 锁 `@eslint/js@^9` |
| `${config_loc}` 未注入 | `Property ${config_loc} has not been set` | pom 加 `propertyExpansion` |
| **路径含中文** | 展开成 `D:\¡Á???\Graduation project\...` 找不到文件 | 改用相对路径 `config_loc=config/checkstyle`，绕开属性展开的编码转换 |

> 第三个坑值得记：项目在"桌面"目录下，`${project.basedir}` 展开时按平台编码转换会破坏中文。CI 在 Linux 上不会有这个问题，但本地会。

| 文件 | 作用 |

### schema 守卫的正反向验证

```
正向：✓ schema 一致（sql/schema.sql == backend/src/main/resources/db/schema.sql）   exit 0
反向：故意往 resources/db 追加一行 → ✗ 两份 schema 不一致 ... exit 1
```

脚本刻意用 POSIX `sh` 写（不用 `<( )` 进程替换、不用 `mktemp`）：
- GitHub Actions 的 `sh` 是 dash，不支持进程替换
- Windows Git Bash 的 `mktemp` 返回 `/tmp/...`，删除时会被路径校验拦截

## 七、刻意没做的事

**这些不是遗漏，是判断。** 理由统一：改动会变更运行时行为或触及产品决策，在答辩前动风险大于收益。

| 项 | 为什么没动 |
| --- | --- |
| **P1-1 N+1 查询** | 改法有三种（缓存 / 联表 / 反范式），选哪种取决于数据量预期。建议先做"补两个 cache"（4 行，81→41 次），再评估是否联表。需你确认后再动 |
| **P1-4 明文口令 → 环境变量** | 改完 `application.yml` 需要本地配 `.env` 才能启动，会打断现有"零依赖跑起来"的演示流程 |
| **P1-5 `DemoDataInitializer` 加 `@Profile`** | README 第 46 行明确写了"首次启动自动建表 + 生成种子数据"。加 `@Profile` 会**改变已文档化的行为**，属于产品决策而非缺陷修复 |
| **P1-6 `sql.init.mode` / `continue-on-error`** | 同上，改成 `never` 会让 MySQL 首次启动建不了表 |
| **P1-7 SQL 日志移出默认 profile** | 移走会削弱本地调试体验；且与 P1-6 同属"profile 分层"整体改造，应一次做 |
| **P1-8 拆 `Dashboard.vue`** | 957 行拆成 5 个 composable 是结构性重构，行为必须保持不变，需要单独一轮 + 逐图对比验证。不适合与安全修复混在同一次改动 |
| **P2 全部 10 项** | 建议级，可拒绝。其中 P2-8（`Login.vue` 硬编码兜底口令）建议顺手改，一行的事 |

> 这几项如果要做，建议按 `04-基线审查报告.md` §七 的 W3/W4 排期，每项单独一个 PR。
